## 해석

새 모델은 전반적으로 더 보수적으로 `정상`을 지키는 경향이 있다.

- 새 모델 `정상` confusion row: `63 / 63` 정답
- 기존 모델 `정상` confusion row: `61 / 63` 정답

반면 기존 모델은 `의심`을 더 잘 잡는다.

- 새 모델 `의심` 정답: `62 / 74`
- 기존 모델 `의심` 정답: `65 / 74`

이 프로젝트 목적이 허위·과장 광고 탐지에 더 가깝다는 점을 고려하면, 현재 결과만 보면 **새 모델은 과탐 방지 측면**, **기존 모델은 위반 탐지 측면**에서 더 유리하다.

## 이번 비교의 한계

이번 비교는 **서비스 파이프라인 전체 기준**이다. 즉, 최종 결과는 KoBERT 단독 성능뿐 아니라 Rule Engine, NLI 보정 결과까지 포함한다.

또한 `training/eval.py`는 현재 서비스 추론 코드와 달리 일부 KoBERT 번들의 `token_type_ids` 처리 예외를 그대로 반영하지 못해, 모델 단독 비교 스크립트로는 바로 재사용하기 어렵다. 따라서 이번 문서는 **실서비스 관점 비교**로 해석하는 것이 맞다.

## 추천 판단

현재 기준 추천:

1. 당장 서비스 모델을 교체하지 말고 기존 모델을 유지한다.
2. 새 모델이 목표한 개선이 무엇이었는지 먼저 분명히 한다.
3. 새 모델의 추가 오답 4건과 기존 모델의 추가 오답 3건을 사람 검수로 다시 분류한다.
4. `의심 recall`을 우선할지, `정상 precision`을 우선할지 운영 기준을 정한다.

## KoBERT 단독 비교

`training/eval.py`는 서비스 추론 코드와 달리 `token_type_ids` 예외를 처리하지 않아 일부 KoBERT 번들을 그대로 평가할 수 없었다. 이 문제를 수정했고, 서비스 파이프라인과 동일하게 `token_type_ids`를 제거한 뒤 curated 평가셋 169건에서 **KoBERT 단독 분류 결과**도 별도로 비교했다.

### 단독 비교 결과

| 항목 | 새 모델 | 기존 모델 | 우세 |
|---|---:|---:|---|
| Accuracy | 0.5385 | 0.2663 | 새 모델 |
| Macro F1 | 0.5279 | 0.2537 | 새 모델 |
| Weighted F1 | 0.5516 | 0.2377 | 새 모델 |

### 단독 비교 해석

이 결과는 파이프라인 비교와 반대다.

- **KoBERT 단독만 보면 새 모델이 훨씬 낫다.**
- **서비스 최종 결과는 기존 모델이 근소하게 더 낫다.**

즉, 현재 파이프라인에서는 KoBERT 자체 품질보다도 **룰 엔진과 NLI 보정이 최종 성능에 미치는 영향이 크다.**

실제로 기존 모델은 KoBERT 단독으로는 curated 셋에서 매우 약하지만, 룰 엔진과 NLI가 붙으면 최종 정확도가 `0.9053`까지 올라간다. 반대로 새 모델은 KoBERT 단독으로는 확실히 좋아졌지만, 그 개선이 현재 보정 구조 안에서는 최종 성능 우위로 이어지지 않았다.

이건 새 모델이 나쁘다는 뜻이 아니라, **현재 파이프라인 튜닝이 기존 KoBERT 분포에 더 맞춰져 있을 가능성**이 높다는 뜻이다.

## 다음 단계

가장 먼저 할 일:

1. `compare_new_pipeline_errors.csv`와 `compare_old_pipeline_errors.csv`를 나란히 보고 어떤 오답이 더 치명적인지 분류한다.
2. 서비스 목표 지표를 정한다.
   - 예: `의심 recall 우선`
   - 예: `정상 과탐 최소화 우선`
3. 새 KoBERT에 맞게 `KoBERT -> NLI 호출 조건`, `score threshold`, `minimum pattern level`이 여전히 적절한지 다시 튜닝한다.
4. 필요하면 새 모델의 학습 데이터 변경점, 증강 방식, 라벨 분포 변화를 같이 비교한다.
5. 여유가 되면 전체 `merged_clean` 검증 분할 기준 모델 단독 비교도 추가로 돌린다.

실무적으로는 1번과 2번이 먼저다. 이 프로젝트는 단순 정확도보다 **어떤 종류의 오탐/미탐을 허용할지**가 더 중요하다.

## 후속 튜닝 실험

오답 분석 후 운영 우선순위를 다음처럼 잡았다.

1. `정상` 과탐 감소보다 `의심` 미탐 감소를 우선한다.
2. 새 KoBERT가 `주의` 규칙 결과를 너무 쉽게 `정상`으로 내리는 현상을 줄인다.
3. `진피층 전달`, `강력투입` 같은 깊은 층 전달/침투 계열 표현은 더 높은 위험 신호로 취급한다.

### 적용한 조정

- `analysis/services/ai_analyzer.py`
  - `주의` 문구가 너무 쉽게 `정상`으로 강등되지 않도록 최소 `주의` 유지 조건 완화
  - 다중 패턴(`matched_patterns >= 2`)인 `주의` 문구는 더 공격적으로 재평가
  - 다중 패턴 문구는 NLI 호출 범위를 넓혀 재검증
- `analysis/services/rule_engine.py`
  - `진피층까지`, `피부 깊은 층 전달`, `강력투입`을 고위 기능성 오인 신호로 추가
