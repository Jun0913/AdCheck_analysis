# 라벨링 판정 정책 2026-04

이 문서는 광고 문구 라벨링과 eval 데이터 정제 기준을 고정하기 위한 운영 문서다.
목표는 아래 3가지다.

1. `정상 / 주의 / 의심` 라벨 기준을 일관되게 유지한다.
2. 실제 광고 문구와 가이드라인 설명문을 분리한다.
3. 재학습 전 데이터 정제 기준을 사람과 코드가 같은 기준으로 공유한다.

## 1. 기본 원칙

- 실제 광고 문구가 아닌 설명문, 지침 문구, 규정 서술문은 메인 eval과 메인 학습셋에서 분리한다.
- `정상 / 주의 / 의심`은 문장 자체의 위험도뿐 아니라 실제 서비스 입력으로 들어왔을 때의 사용자 오인 가능성을 기준으로 정한다.
- 허용 예외 표현은 일반 패턴보다 우선한다.
- 경계 사례는 억지로 한쪽으로 밀기보다 `severity_boundary`로 먼저 표시하고 정책 확정 후 반영한다.

## 2. 버킷 정의

### `meta_guideline`
- 실제 광고 카피가 아니라 지침 설명, 금지 사례 해설, 메타 문장에 가까운 경우
- 메인 eval에서 제외하거나 별도 eval로 분리한다

예시:
- `제품 사용방법을 사실과 다르거나 오인할 수 있는 표현 추가`
- `저속하거나 혐오감을 주는 표시 및 광고`
- `남녀의 성행위를 묘사하는 표시 또는 광고`

### `allow_conflict`
- 현재 시스템은 경고하지만, 기준상 허용 또는 조건부 허용 문구로 유지할 수 있는 경우
- 허용 예외 문구 테이블을 우선 확정한다

예시:
- `주름개선 도움`
- `보습을 통해 피부건조에 기인한 가려움의 일시적 완화에 도움`
- `빠지는 모발을 감소`
- `우유 엑소좀, 식물 엑소좀 등`

### `true_miss`
- 실제 광고문구인데 현재 시스템이 `정상`으로 남기거나 도메인 밖으로 보내는 경우
- 룰 또는 패턴 보강 우선순위가 높다

예시:
- `기미 부분의 피부를 녹여 딱지를 생기게 한 뒤 뜯어내는 제품`
- `3D 롤스탬프 사용 후 에센샷 앰플`
- `관절, 림프선 등 피부 이외 신체 특정 부위에 사용하여 의학적 효능, 효과 표방`

### `severity_boundary`
- 광고문구는 잡았지만 `주의`와 `의심` 경계가 애매한 경우
- 재학습과 패턴 강도 조정의 핵심 대상이다

예시:
- `탈모 샴푸`
- `Botox 크림`
- `모발 생성이 426% 증가`
- `코스메슈티컬(cosmeceutical)`

## 3. 라벨 정의

### `정상`

아래 중 하나에 해당하면 기본적으로 `정상`이다.

- 식약처 가이드에서 허용 예시로 명시된 표현
- 기능성 범주 안에서 조건부 허용되는 표현
- 단순 제품 설명, 제형 설명, 사용감 설명
- 의미 있는 광고 클레임이 아닌 안내성 문구

예시:
- `피부 보습에 도움`
- `주름 완화 또는 개선`  (정책상 허용으로 확정한 경우)
- `빠지는 모발을 감소`  (정책상 허용으로 확정한 경우)
- `촉촉한 사용감`

### `주의`

아래 중 하나에 해당하면 기본적으로 `주의`다.

- 과장 가능성은 있으나 즉시 금지로 단정하기 어려운 기능성 표현
- 문맥에 따라 허용/비허용이 갈릴 수 있는 경계 문구
- 과장 수치나 강한 기능성 주장이 있으나 평가 정책상 `의심`까지는 올리지 않기로 한 경우

예시:
- `피부 재생 및 피부결 개선`
- `모발 수 증가`
- `모발 두께 증가`
- `손상된 피부 집중 재생`

### `의심`

아래 중 하나에 해당하면 기본적으로 `의심`이다.

- 질병 치료·예방·완화 오인
- 병원/전문의/의사 추천, 개발, 인증, 전용 표현
- 보톡스, 메디슨, 코스메슈티컬처럼 의약품/시술/의료 이미지를 직접 차용
- 신체 내부 전달, 진피층 침투, 물리적 제거, 지방분해, 모낭·성장인자 조절 같은 공격적 기능성 주장
- 수치 과장, 즉시 효과, 완치, 100%, 완전 제거

예시:
- `여드름 치료`
- `병원전용 화장품`
- `Botox 크림`
- `모발 생성이 426% 증가`
- `즉각 세균 99.9% 억제율`

## 4. 검수 순서

`reports/eval_set_mismatches_review.csv`에서 아래 순서로 본다.

1. 실제 광고 문구인지 확인
2. 실제 광고가 아니면 `human_bucket=meta_guideline`
3. 실제 광고면 허용 예외 문구인지 확인
4. 허용 예외면 `human_bucket=allow_conflict`
5. 시스템이 놓친 경우 `human_bucket=true_miss`
6. 시스템이 잡긴 했지만 강도가 다른 경우 `human_bucket=severity_boundary`

## 5. 검수 컬럼 사용법

파일:
- `reports/eval_set_mismatches_review.csv`

사람이 채워야 할 컬럼:
- `human_bucket`
- `human_note`

권장 값:
- `meta_guideline`
- `allow_conflict`
- `true_miss`
- `severity_boundary`
- 필요하면 `label_fix_normal`, `label_fix_caution`, `label_fix_suspicious`

`human_note`에는 아래 중 하나를 적는다.
- 허용 예외로 유지
- 메인 eval 제외
- 룰 추가 필요
- 의심 승격 필요
- 라벨 재검토 필요

## 6. 정제 후 산출물

검수 완료 후에는 아래 파일을 만든다.

- `data/eval/eval_candidates_curated.csv`
  - 메인 성능 측정용
- `data/eval/eval_candidates_meta.csv`
  - 설명문/가이드 문구
- `data/eval/eval_candidates_boundary.csv`
  - 경계 사례 모음

## 7. 재학습 전 체크리스트

- `meta_guideline` 문장을 학습셋에서 제외했는가
- `allow_conflict` 문장을 허용 정책과 일치시켰는가
- `true_miss` 문장을 적절한 라벨로 보강했는가
- `severity_boundary` 문장을 `주의/의심` 기준에 맞게 재정렬했는가
- 정제된 eval 셋으로 성능을 다시 측정했는가
